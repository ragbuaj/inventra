# Rencana Implementasi: PWA untuk aplikasi web Inventra

- Tanggal: 2026-08-27
- Spec: `docs/superpowers/specs/2026-08-27-web-pwa-design.md` (40 acceptance criteria, tanpa pertanyaan terbuka)
- Branch: `feat/web-pwa`
- Fase: Plan (`/plan`). Belum ada kode yang ditulis saat dokumen ini dibuat.

## Ikhtisar

Menjadikan aplikasi web Inventra sebuah PWA berkedalaman "installable dan andal": bisa
dipasang ke layar utama Android dan iOS, aset build beserta shell ter-precache, jaringan
putus memberi shell aplikasi alih-alih halaman error browser, dan deploy baru sampai ke
pengguna lewat ajakan yang mereka kendalikan. **Tidak ada satu pun respons API yang
di-cache.** Web Push, antrean tulis offline, dan perubahan backend berada di luar cakupan.

Pekerjaan ini seluruhnya di `frontend/` plus dokumen. Backend, migrasi, OpenAPI, dan
aplikasi Flutter tidak disentuh sama sekali.

## Keputusan arsitektur

Sebelas keputusan sudah dikunci di spec. Empat di antaranya yang paling menentukan bentuk
tugas di bawah:

1. **Shell dipaksa jadi berkas statis lewat prerender rute `/`.** `nuxt build` hari ini
   tidak menghasilkan satu pun HTML di `.output/public/` — shell dirender Nitro saat
   runtime, sehingga tidak ada yang bisa di-precache. Karena `ssr: false`, HTML hasil
   prerender hanyalah kerangka kosong tanpa data pengguna.
2. **`registerType: 'prompt'`, bukan `autoUpdate`.** Muat ulang otomatis bisa membuang
   isian formulir aset yang sedang diketik.
3. **Tidak ada runtime caching apa pun.** Konsekuensi kerasnya: `Cache Storage` wajib nol
   entri ber-URL mengandung `/api/`. Ini dibuktikan lewat pembacaan `caches` di e2e, bukan
   diperiksa mata — sebab di produksi API se-origin dengan frontend, sementara di dev beda
   origin, jadi kesalahan semacam ini tidak akan pernah terlihat saat dev.
4. **Ikon diturunkan dari mark aplikasi yang sudah ada**, bukan dari logo korporat BTN dan
   bukan karya visual baru.

## Konvensi yang berlaku di seluruh tugas

- Commit per tugas, Conventional Commits berscope: `feat(pwa): ...`, `test(pwa): ...`,
  `docs(pwa): ...`.
- Tiap tugas ditutup dengan `pnpm lint`, `pnpm typecheck`, `pnpm test`, `pnpm build` hijau
  dari `frontend/`.
- Tiap string baru masuk `i18n/locales/id.json` dan `en.json` di bawah namespace `pwa`.
- UI disusun dari komponen `U*` Nuxt UI.
- **e2e lokal wajib `--workers=1`** seperti CI, dan backend wajib `RATELIMIT_ENABLED=false`.
- Tes baru wajib dibuktikan bisa merah lewat mutasi terarah sebelum dianggap selesai.

### Tugas 1: Buktikan `@vite-pwa/nuxt` bekerja di Nuxt 4

**Deskripsi:** Tugas berisiko tertinggi, sengaja ditaruh paling depan supaya gagalnya
murah. `@vite-pwa/nuxt@1.1.1` menyatakan ketergantungan `@nuxt/kit` ^3.9.0 dan dikembangkan
terhadap Nuxt ^3.10; dukungan Nuxt 4 tidak dinyatakan resmi di metadata paketnya walau
dipakai luas. Pasang modul dengan konfigurasi paling minimal, jalankan build, dan buktikan
service worker beserta manifest benar-benar terbit. Belum ada UI, belum ada ikon sungguhan.

**Acceptance criteria:**
- [ ] `pnpm build` selesai tanpa error dengan modul terpasang.
- [ ] `.output/public/sw.js` dan `.output/public/manifest.webmanifest` benar-benar ada setelah build.
- [ ] `pnpm dev` berjalan normal dan **tidak** mendaftarkan service worker.

**Verifikasi:**
- [ ] `pnpm build` lalu `ls .output/public/` memperlihatkan kedua berkas.
- [ ] `pnpm lint`, `pnpm typecheck` hijau.
- [ ] Gerbang keputusan: kalau salah satu gagal, hentikan jalur modul dan pakai
      `vite-plugin-pwa` langsung lewat `vite.plugins` plus plugin Nuxt untuk pendaftaran,
      lalu sesuaikan tugas 3 dan 4 sebelum melanjutkan. Catat hasilnya di rencana ini.

**Ketergantungan:** Tidak ada.

**Berkas yang kemungkinan disentuh:**
- `frontend/package.json`
- `frontend/pnpm-lock.yaml`
- `frontend/nuxt.config.ts`

**Perkiraan cakupan:** S

**HASIL GERBANG (2026-08-27): LULUS, dengan dua penghalang yang harus dibongkar dulu.**
Keduanya ternyata bukan soal dukungan Nuxt 4, dan yang pertama membuat jalur cadangan yang
ditulis rencana ini **tidak akan menolong** — `vite-plugin-pwa` langsung memakai
`workbox-build` yang sama, jadi ia akan gagal dengan cara yang persis sama.

1. Build berhenti dengan "Unable to write the service worker file". Override keamanan
   `'@babel/core': '>=7.29.1'` di `pnpm-workspace.yaml` tidak berbatas atas, sehingga pnpm
   menariknya ke `@babel/core` 8, sementara `workbox-build@7.4.1` menuntut `^7.24.4` dan
   `@rollup/plugin-babel` menolak. Tidak ada satu pun paket di pohon ini yang menuntut `^8`.
   Diperbaiki dengan override **berlingkup** `workbox-build>@babel/core: '>=7.29.1 <8'`,
   sehingga lantai keamanan tetap utuh dan paket lain tidak berubah.
2. Seluruh 86 berkas tes runtime Nuxt mati saat boot: plugin klien modul mengimpor virtual
   module `virtual:pwa-register/vue`, yang diserahkan runtime tes ke module loader Node
   sebagai nama berkas. Diperbaiki lewat sakelar resmi modul,
   `pwa.client.registerPlugin: false`, khusus di lingkungan tes.

Sesudahnya: `pnpm build` menerbitkan `sw.js` dan `manifest.webmanifest`, dan `pnpm dev`
tidak menyajikan maupun mendaftarkan service worker (`/sw.js` di dev jatuh ke SPA fallback
Nitro, bukan berkas service worker).

### Tugas 4: Shell statis, precache, dan denylist

**Deskripsi:** Paksa rute `/` di-prerender sehingga shell menjadi berkas HTML statis yang
bisa di-precache, lalu setel Workbox: `globPatterns` untuk aset build, `navigateFallback` ke

aktif, `registerType: 'prompt'`, dan `devOptions` mati. Tidak boleh ada satu pun aturan
runtime caching.

**Acceptance criteria:**
- [ ] Setelah `pnpm build`, ada berkas HTML shell statis di `.output/public/` dan ia masuk daftar precache.
- [ ] Precache berisi aset build (JS, CSS, font, ikon) dan **nol** entri ber-URL mengandung `/api/`.
- [ ] Konfigurasi tidak memuat satu pun aturan runtime caching.
- [ ] `navigateFallbackDenylist` mengecualikan `/api/` dan `/health`.
- [ ] Shell hasil prerender tidak memuat data pengguna apa pun (dibaca langsung, bukan diasumsikan dari `ssr: false`).

**Verifikasi:**
- [ ] Baca daftar precache di `.output/public/sw.js` yang dibangun, pastikan isinya sesuai dan tidak memuat `/api/`.
- [ ] Buka shell HTML hasil prerender, pastikan hanya kerangka kosong.
- [ ] `pnpm preview`, muat sekali, lalu matikan jaringan di DevTools dan muat ulang: shell tetap tampil.
- [ ] `pnpm dev`: pastikan service worker tidak terdaftar.
- [ ] `pnpm lint`, `pnpm typecheck`, `pnpm test`, `pnpm build` hijau.

### Tugas 5: e2e service worker, offline, dan keamanan cache

**Deskripsi:** Spec e2e tersendiri yang membuktikan perilaku yang tidak bisa dibuktikan tes
unit: service worker benar-benar aktif, offline benar-benar memberi shell, dan yang
terpenting **Cache Storage benar-benar bersih dari `/api/`** setelah dipakai login dan
membuka layar berdata. Ini tes keamanan, bukan tes kenyamanan.

**Acceptance criteria:**
- [ ] Manifest terlayani 200, JSON-nya terurai, bidang wajibnya benar; setiap URL ikon menjawab 200 dengan tipe gambar.
- [ ] Service worker mencapai `activated` dalam batas waktu wajar.
- [ ] Setelah login dan membuka layar berdata, pembacaan `caches` lewat `page.evaluate`
      memberi **nol** entri ber-URL mengandung `/api/` — diperiksa sebelum dan sesudah logout.
- [ ] Offline setelah satu kunjungan daring: navigasi menampilkan shell aplikasi, bukan halaman error browser.
- [ ] Offline: layar berdata menampilkan keadaan error aplikasi, bukan data basi.
- [ ] Rute `/en/` bekerja offline dengan shell yang sama.
- [ ] Muat ulang daring setelah offline mengembalikan keadaan normal.

**Verifikasi:**
- [ ] `pnpm exec playwright test e2e/pwa.spec.ts --workers=1` hijau, dijalankan tiga kali berturut-turut untuk menyaring kerapuhan.
- [ ] Tiap tes dibuktikan bisa merah lewat mutasi terarah — minimal: hapus satu entri
      denylist, dan tambahkan satu aturan runtime caching untuk `/api/`; keduanya harus
      membuat tes keamanan cache gagal. Kembalikan setelahnya.
- [ ] Data uji dibersihkan sendiri di `afterAll` bila tes sempat membuat data.

**Ketergantungan:** Tugas 4.

**Berkas yang kemungkinan disentuh:**
- `frontend/e2e/pwa.spec.ts`
- `frontend/e2e/helpers.ts` (hanya bila butuh helper baru)

**Perkiraan cakupan:** M

**Menutup acceptance criteria spec:** 15, 17, 18, 20, 21, 22, plus pembuktian 12 dan 16.

## Risiko dan mitigasi

| Risiko | Dampak | Mitigasi |
|---|---|---|
| `@vite-pwa/nuxt` tidak jalan di Nuxt 4 | Tinggi | T1 adalah gerbang paling depan; jalur cadangan `vite-plugin-pwa` sudah ditetapkan sebelum pekerjaan lain dimulai |
| Service worker menggoyahkan 40 spec e2e yang ada | Tinggi | T9 tugas tersendiri, dijalankan dua kali berturut-turut, dan dilarang melonggarkan spec lama |
| Respons API tak sengaja ter-cache di produksi | Tinggi | Di produksi API se-origin sehingga kesalahan ini tak terlihat saat dev; T5 membuktikannya lewat pembacaan `caches` dan mutasi yang harus membuatnya merah |
| Prerender rute `/` membocorkan sesuatu ke HTML statis | Sedang | AC eksplisit di T4: shell hasil prerender dibaca langsung, bukan diasumsikan aman karena `ssr: false` |
| Glyph maskable terpotong saat Android memotongnya jadi lingkaran | Rendah | AC di T2 dengan uji potong lingkaran 80 persen, plus pemeriksaan di perangkat nyata di T11 |
| WAF Coraza memblok manifest atau sw.js | Sedang | Hanya ketahuan di produksi; T11 menjadikannya langkah wajib, bukan opsional |
| Poles safe-area diam-diam mengubah tata letak non-standalone | Rendah | AC di T8: bandingkan tampilan non-standalone sebelum dan sesudah, harus identik |
